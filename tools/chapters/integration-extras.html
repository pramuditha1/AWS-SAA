Integration extras — AppSync, MSK, and AppFlow

Should / nameDomain 2 · when SQS/API Gateway is not the named fit

Default SAA decoupling is SQS, SNS, EventBridge, Kinesis, and API Gateway. These three extras appear when the stem names GraphQL, Apache Kafka, or “pull Salesforce into S3 without writing Glue.”

Start here — the W questions

Why

Mobile apps want GraphQL subscriptions. Kafka estates refuse a rewrite to Kinesis. SaaS admins want scheduled sync without custom connectors.

What

AWS AppSync — managed GraphQL (and real-time subscriptions). Amazon MSK — managed Apache Kafka. Amazon AppFlow — no-code SaaS ↔ AWS data flows.

Where

Regional managed services. MSK brokers live in your VPC. AppSync is an AWS endpoint in front of data sources (DynamoDB, Lambda, HTTP). AppFlow runs in a Region to S3/Redshift/etc.

Which pieces matter

GraphQL → AppSync · Kafka API → MSK · AWS-native stream → Kinesis · SaaS to S3 → AppFlow. Do not pick both MSK and Kinesis for the same constraint.

Case study 2 — GraphQL mobile

Stem

A — wrong Hand-rolled API Gateway + WebSockets.
B — correct AWS AppSync with DynamoDB data source.
C — wrong MSK as the client API.
D — wrong AppFlow.
Remember Kafka API → MSK. AWS-native stream → Kinesis. GraphQL → AppSync. SaaS sync → AppFlow.

Tricky points

MSK ≠ Amazon MQ. MQ is ActiveMQ/RabbitMQ/JMS. Kafka clients need MSK (or self-managed Kafka).

AppFlow ≠ DMS. DMS moves databases. AppFlow moves SaaS application data.

AppSync ≠ API Gateway REST. When the stem says GraphQL/subscriptions, AppSync is the managed fit.
