Machine learning on AWS — pick the API, not the math

Should-knowDomain 3 · managed AI services

SAA does not ask you to train neural nets by hand. It asks which managed API matches a sentence: see an image, hear speech, speak text, translate, chatbot, forecast, or custom model training. Match the verb to the service.

Start here — the W questions

Why

Building OCR, speech, or translation from scratch is slow. AWS sells ready APIs so architects can add “detect faces” or “transcribe the call” without an ML team.

What

A catalog of AI services (Rekognition, Transcribe, Polly, Translate, Comprehend, Lex, Textract, Forecast, Fraud Detector, and friends) plus SageMaker when you must build/train/host your own models.

Where

These APIs are Regional endpoints. You send data to the service (watch residency). SageMaker training/hosting runs in your account’s Region.

Which pieces matter

Rekognition · Textract · Transcribe/Polly · Translate · Comprehend · Lex · SageMaker · Forecast. Amazon Personalize is out of scope / low value for SAA — do not study it deeply.

Core knowledge (beginner foundations)

Prebuilt API vs SageMaker

If the stem describes a common capability AWS already sells, pick that service. If it says bring your own algorithm, custom training data, notebooks, and hosted endpoints you control, pick SageMaker.

Out of scope / low value Amazon Personalize (recommendations). Know the name exists; do not deep-dive recipes or campaigns for SAA.

Use cases

Moderation: User uploads → Rekognition content moderation → store or reject.

Call analytics: Transcribe → Comprehend for sentiment → dashboard.

Accessibility: Polly reads articles aloud; Translate for locales.

Forms: Textract on invoices into structured fields (not Rekognition — that is scenes/faces).

Tricky points

Rekognition ≠ Textract. Pictures of things vs reading documents.

Transcribe ≠ Polly. Opposite directions.

Lex is NLU chatbots; it is not the general “train any model” answer.

Personalize: treat as out of scope / low value for SAA study time.
