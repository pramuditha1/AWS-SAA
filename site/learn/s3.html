Amazon S3 — object storage for almost every app

Must-knowDomains 1–4 · Secure, resilient, performance, and cost

Amazon S3 is AWS’s object storage service. You put files (objects) in buckets and read them by key. On the exam you choose a storage class, an encryption mode, a private access path, and — when needed — replication or immutability that still meet every constraint in the stem.

Start here — the W questions

Why

Apps need a place for backups, logs, images, data lakes, and static websites. Disks on one server do not scale, and they die with that server. You want durable storage you address by name, not by a block device.

What

Amazon S3 (Simple Storage Service) stores objects — a key (the name), the bytes, and metadata — inside a bucket. You talk to it over HTTPS with the API, an SDK, the console, or a VPC endpoint. There are no real folders; slashes in a key are just characters that create a useful prefix.

Where

A bucket lives in one Region you choose at create time. The bucket name is globally unique across AWS; the data is Regional. Multi-AZ classes store copies across Availability Zones in that Region. Cross-Region needs replication or a copy you control.

Which pieces matter

Bucket + object · storage class · encryption (SSE-S3 / SSE-KMS) · Block Public Access · versioning / Object Lock · CRR/SRR · gateway VPC endpoint. Those cover almost every SAA S3 question.

Core knowledge (beginner foundations)

Object storage in one breath

You create a bucket in a Region, then PUT objects into it. Each object has a key like incoming/2026/photo.jpg. Clients GET by key. S3 is not a file system and not a block volume — it is a huge, durable key/value store for bytes. Since December 2020, new PUTs, overwrites, and DELETEs are strongly consistent: if you PUT and immediately GET, you see the new data.

Durability vs availability — Durability means “will the object still exist next year?” Multi-AZ classes are designed for 11 nines of durability. Availability means “can I GET it right now?” An AZ network blip can hurt availability without destroying the object.

Storage class — a per-object setting that trades price, retrieval time, and AZ behavior. Standard for frequent access; Intelligent-Tiering when access is unknown; IA and Glacier classes when you read less often or can wait.

Multipart upload — required above 5 GB (max object is 5 TB). AWS also recommends it above ~100 MB so failed parts retry without restarting the whole upload.

How traffic reaches a bucket (from AWS docs)

Applications call the S3 API. From a private subnet you usually want traffic to stay on the AWS network. The cheap path for same-Region S3 is a gateway VPC endpoint — a route-table prefix list with no hourly charge.

flowchart LR app[App_or_user] --> api[S3_API_SDK] api --> bucket[Regional_bucket] bucket --> obj[Object_by_key] priv[Private_EC2] --> rtb[Route_table] rtb --> gwep[Gateway_endpoint_S3] gwep --> bucket

Bucket basics: What is Amazon S3? Gateway path: Gateway endpoints for Amazon S3.

If the stem is “EC2 in private subnets must read S3, minimize cost, no internet,” pick the gateway endpoint. An interface endpoint (PrivateLink) for S3 also exists, costs money, and is the tool when on-premises clients need a private IP over Direct Connect or VPN. Do not send same-Region S3 through a NAT Gateway when a gateway endpoint will do.

Storage classes — choose by constraints, then cost

Meet every constraint first (AZ loss, retrieval time, minimum duration). Only then pick the cheaper class. Multi-AZ in one Region is high availability — not disaster recovery. Cross-Region Replication is the DR answer.

Encryption and who can read the bucket

New uploads default to SSE-S3 (Amazon-managed keys). Choose SSE-KMS with a customer-managed key when the stem wants a key policy, cross-account decrypt, or CloudTrail of who used the key. SSE-C means you provide the key on every request; AWS does not store it. Client-side encryption means AWS never sees plaintext.

S3 Block Public Access can sit on the account and the bucket. When it is on, a bucket policy with Principal: * does not make the bucket public. For CloudFront in front of a private bucket, use Origin Access Control (OAC): the distribution signs requests; the bucket policy allows only that distribution.

See Protecting data with encryption and Block Public Access.

Versioning, Object Lock, and replication

Versioning keeps prior versions when you overwrite or delete (a delete without a version ID writes a delete marker). You can suspend versioning; you cannot return to “never versioned.”

MFA Delete requires the root user to enable. It is not a substitute for Object Lock.

Object Lock is WORM. Governance mode can be bypassed with a special permission. Compliance mode cannot — not even by root — until the retain-until date. A legal hold has no expiry until someone with permission lifts it.

SRR / CRR need versioning on source and destination. New objects replicate; existing ones need Batch Replication. Delete-marker replication is off by default. CRR is Regional DR; SRR is same-Region aggregation or ownership split.

Use case 1 — private path from EC2

Need: Private subnets, same-Region bucket, no internet, lowest cost.

Design: Gateway VPC endpoint on the private route tables. Optional bucket policy condition on aws:SourceVpce.

flowchart LR ec2[Private_EC2] --> rtb[Route_table] rtb --> gw[Gateway_endpoint] gw --> s3[S3_same_Region]

Use case 2 — static site with HTTPS, bucket stays private

Need: Custom domain, HTTPS, global cache, origin in S3, bucket not public.

Design: CloudFront + OAC + ACM cert on CloudFront. Bucket policy allows only that distribution. S3 website hosting alone is HTTP-only.

Use case 3 — partner upload for fifteen minutes

Need: One PUT from a partner without a public bucket or standing keys in the browser.

Design: Backend that already has IAM permission mints a pre-signed PUT URL. Time-boxed; inherits the signer’s permission.

Case study 1 — class that survives the constraints

Stem

Master videos cannot be recreated (~4 GB) and are read several times a week. Thumbnails can be regenerated. Masters must survive AZ failure. Finance wants the lowest storage cost that still meets those rules.

A — wrong Masters and thumbnails in One Zone-IA.
B — wrong Masters in Glacier Flexible Retrieval; thumbnails in Standard.
C — correct Masters in Standard (or Intelligent-Tiering if access varies); thumbnails in One Zone-IA. No Reduced Redundancy.
D — wrong Both in Standard-IA because it is multi-AZ and cheaper than Standard.

A fails AZ loss on masters. B fails weekly editor reads (restore delay). D charges retrieval fees for frequent access. C meets every constraint first.

Case study 2 — private path without burning money

Stem

EC2 in private subnets in two AZs must GetObject and PutObject against a same-Region bucket. No internet gateway today. Security forbids the public internet. Lowest ongoing cost. No on-premises private-IP requirement.

A — wrong Add IGW + NAT Gateway; send S3 through NAT.
B — wrong Interface VPC endpoint for S3 in both AZs.
C — correct Gateway VPC endpoint for S3 on the private route tables; optional aws:SourceVpce on the bucket policy.
D — wrong Transfer Acceleration from the instances.

A violates “no public internet” and costs hourly. B works but bills per AZ. D is for distant clients and still uses public endpoints. C is the free same-Region path.

Case study 3 — immutability root cannot undo

Stem

A bank must keep trade records seven years. Objects must be impossible to delete or overwrite — including by administrators and root. E-discovery holds must persist after the seven-year date if a case is still open.

A — wrong Versioning + MFA Delete; give root to compliance.
B — wrong Object Lock Governance mode for seven years.
C — correct Object Lock Compliance mode for seven years, plus legal holds for e-discovery. Versioning comes with Object Lock.
D — wrong CRR to another account and deny DeleteObject in identity policies.

A still lets root delete with MFA. B is bypassable. D can be changed by an admin. C matches Compliance-mode WORM plus legal hold.

Tricky points (still explained simply)

Meet every constraint, then optimize cost. Millisecond reads kill Deep Archive. AZ-failure tolerance kills One Zone-IA for the only copy. Region failure needs CRR — Multi-AZ is not DR.

Intelligent-Tiering has no retrieval fee but charges monitoring for eligible objects. Under 128 KB stays in Frequent Access.

Glacier is three products. Instant Retrieval = GET in milliseconds. Flexible and Deep Archive need a restore job first.

Replication is not a time machine. Enable versioning first. Old objects need Batch Replication. RTC is an optional 15-minute SLA, not the default.

SSE-S3 is default; SSE-KMS is the audit / key-policy answer.

Notifications go to Lambda, SQS, SNS, or EventBridge — not straight to Step Functions or an EC2 HTTP endpoint as a first-class destination.

Gateway endpoints are same-Region only and exist for S3 and DynamoDB. Cross-Region GET is a different path and you pay transfer.

Exam habit When two S3 answers both store the object safely, keep the one that also matches retrieval time, AZ/Region scope, and who pays. Write “HA ≠ DR” next to every Multi-AZ stem.
Light touch on the exam Exact restore-minute tables, S3 Express One Zone internals, every Batch Operations job type. Know the class family and when restore is required.
