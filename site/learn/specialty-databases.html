Learn / Specialty DBs

Specialty databases — DocumentDB, Neptune, Keyspaces

Know the nameDomain 3 · purpose-built engines

SAA will not ask you to tune Cassandra compaction. It will give one sentence of data model and expect the matching AWS engine. SQL joins → RDS/Aurora. Key-value at scale → DynamoDB. This page is the leftover: MongoDB API, graph, or Cassandra/CQL.

Start here — the W questions

Why

One database shape does not fit graphs, documents, and wide-column workloads. Forcing them into SQL or DynamoDB when the stem names another API is the wrong answer.

What

DocumentDB — MongoDB-compatible documents. Neptune — graph (Gremlin/SPARQL). Keyspaces — Apache Cassandra-compatible (CQL).

Where

Managed clusters/tables in a Region (VPC for DocumentDB/Neptune). Pick by API/model, not by “JSON somehow.”

Which pieces matter

MongoDB drivers → DocumentDB · friend/fraud graph → Neptune · Cassandra/CQL → Keyspaces. That is the whole SAA surface.

How to choose

If the app already speaks…PickNot
MongoDB drivers, collections, documentsDocumentDBDynamoDB rewrite; RDS JSONB as “Mongo”
Highly connected graph, Gremlin/SPARQLNeptuneRecursive SQL forever; DynamoDB adjacency as “graph DB”
Cassandra / CQL / wide-columnKeyspacesDynamoDB unless they want the AWS-native API

Case study 1 — MongoDB migrate

Stem

On-premises MongoDB; minimal app change; managed on AWS.

A — wrong DynamoDB single-table rewrite.
B — correct Amazon DocumentDB (MongoDB compatible).
C — wrong RDS PostgreSQL JSONB only.
D — wrong Neptune.

Case study 2 — fraud graph

Stem

Analysts query multi-hop payment/device relationships with Gremlin at low latency.

A — wrong RDS recursive CTEs as the named solution.
B — correct Amazon Neptune.
C — wrong DynamoDB adjacency lists while keeping Gremlin.
D — wrong Redshift.
Exam habit Named third-party API → compatibility service. Named access pattern (key-value, graph, SQL) → AWS-native service.

Tricky points

JSON in Postgres is not MongoDB. DocumentDB keeps MongoDB drivers working.

OpenSearch is search/logs, not on this specialty-DB page — see Analytics when the stem is full-text.

Timestream / QLDB / MemoryDB are name-level only if they appear; do not deep-dive.
