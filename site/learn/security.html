KMS, WAF, Shield, and detective security services

Must-knowDomain 1 · Tasks 1.2–1.3 · 30% of the exam

A large part of Domain 1 is not IAM. It is how you encrypt data, how you stop Layer-7 abuse and DDoS, how you store rotating secrets, and how you detect trouble after it starts. This chapter teaches those controls as simple jobs: prevent, detect, and keep secrets safe.

Start here — the W questions

Why

Data leaks, SQL injection, floods of traffic, and leaked database passwords are everyday risks. You need managed tools so every team does not invent its own crypto and firewall.

What

KMS manages encryption keys. ACM issues TLS certificates for AWS front doors. WAF filters bad HTTP. Shield mitigates DDoS. GuardDuty / Inspector / Macie / Security Hub detect and aggregate findings. Secrets Manager and Parameter Store hold secrets and config.

Where

KMS keys are regional. WAF attaches to CloudFront (global edge), ALB, API Gateway, or AppSync. Shield Standard is automatic on supported services. Detective services run in your accounts and feed Security Hub, often from an Organizations delegated admin.

Which pieces matter

Envelope encryption · CMK vs AWS managed vs AWS owned · WAF vs Shield · GuardDuty vs Inspector vs Macie · Secrets Manager vs Parameter Store · Firewall Manager for org-wide policy. Those forks decide most stems.

Core knowledge (beginner foundations)

Preventive vs detective

Preventive controls stop a class of attack: KMS/ACM for confidentiality, WAF for SQLi/XSS, Shield for volumetric DDoS, private subnets and security groups for network exposure. Detective controls tell you something already looks wrong: GuardDuty, Inspector, Macie, Security Hub. You usually need both.

Envelope encryption — encrypt big data with a short-lived data key; encrypt that data key with a KMS key. KMS’s direct Encrypt API only accepts about 4 KB of plaintext, so bulk data never goes to KMS as one blob.

Customer managed key (CMK) — you create it, you set the key policy, you can share and rotate on your terms. Exam stems that need audit and revoke usually want a CMK (SSE-KMS).

Web ACL — the WAF rule set you attach to a supported front door.

Shield Standard — free, automatic Layer 3/4 DDoS protection. Shield Advanced — paid; DRT help and cost protection during large attacks.

How envelope encryption works (from AWS docs)

AWS documents a generate-data-key pattern: ask KMS for a data key, encrypt data locally, store the encrypted data key with the ciphertext, later ask KMS to unwrap the data key.

sequenceDiagram participant App participant KMS participant Disk App->>KMS: GenerateDataKey KMS-->>App: PlaintextDEK_and_EncryptedDEK App->>Disk: Write ciphertext plus EncryptedDEK App->>KMS: Decrypt EncryptedDEK KMS-->>App: PlaintextDEK App->>App: Decrypt data locally

Follows KMS envelope encryption. S3/EBS/RDS SSE-KMS do this dance for you when you enable it.

A KMS key policy is required. An IAM identity policy alone is not enough unless the key policy allows the caller (or delegates to IAM). Keys and ciphertext are regional unless you use multi-Region keys.

CloudHSM is for single-tenant HSM or PKCS#11 needs. Do not pick it for ordinary SSE.

Remember Identity policy + missing key-policy allow = Decrypt fails. Same Region matters unless you planned multi-Region keys.

ACM — TLS certificates for AWS front doors

ACM issues and renews public certificates for names you prove you own (DNS validation is common). Attach them to CloudFront, ALB, NLB TLS listeners, API Gateway custom domains. You do not download an ACM-issued public private key onto EC2. CloudFront certificates must be in us-east-1. ALB certificates live in the load balancer’s Region.

WAF and Shield — different layers

WAF inspects HTTP/HTTPS (Layer 7): SQLi, XSS, rate limits, geo, IP sets, managed rule groups. Attach to CloudFront, ALB, API Gateway, or AppSync — not to an NLB alone.

Shield Standard is always on for common L3/L4 DDoS on supported services (especially CloudFront, ALB, Route 53). No ticket to enable. Shield Advanced adds DRT, richer telemetry, and cost protection — not SQLi rules (that is still WAF).

Detective services — do not mix the sensors

GuardDuty — threat findings from CloudTrail, VPC Flow Logs, DNS (and more). “Crypto mining,” “stolen key used abroad.” Not a CVE scanner.

Inspector — CVE and network reachability on EC2, ECR images, Lambda. “Scan for missing patches.”

Macie — sensitive data (PII) in S3. Not EBS in place.

Security Hub — aggregates findings and runs security standards (CIS, foundational best practices). Central pane of glass — does not replace the sensors.

Secrets Manager versus Parameter Store

Secrets Manager — secrets with lifecycle: automatic rotation (including RDS/Aurora integration), resource policies, cross-account share. Stem says “rotate DB password every 30 days” → Secrets Manager.

Parameter Store — hierarchical config (/app/prod/url). SecureString uses KMS. Cheap. You rotate yourself. Not the managed RDS rotation contract.

Firewall Manager — Organizations policy that forces WAF, Shield Advanced associations, or security-group baselines onto every account/OU. Use when “every ALB must get this web ACL, including next month’s accounts.”

Use case 1 — encrypt large objects with audit

Need: Encrypt 50 MB documents; audit key use; revoke by denying one key.

Design: Customer managed key + envelope encryption (or SSE-KMS). Not kms:Encrypt on the whole 50 MB. Not SSE-S3 if you need a key you can revoke.

Use case 2 — SQLi plus big DDoS on API Gateway

Need: Block injection patterns; AWS help and cost protection on large DDoS; stay on API Gateway.

Design: WAF web ACL on API Gateway + Shield Advanced on supported resources. Shield Standard is already free.

Case study 1 — envelope encryption

Stem

An app must encrypt 50 MB JSON before S3. Compliance needs CloudTrail key audit and the ability to revoke historical access by denying one key. Developers want to call kms:Encrypt on the whole document.

A — wrong Call kms:Encrypt with the document as plaintext — size is not a limit.
B — correct Customer managed key; GenerateDataKey / SSE-KMS envelope; key policy + CloudTrail for audit and revoke.
C — wrong SSE-S3; revoke the AWS owned key from the S3 console.
D — wrong CloudHSM on every host because 50 MB is “large.”

Case study 2 — WAF plus Shield Advanced

Stem

API Gateway + Lambda saw SQLi-like query strings and a volumetric flood that inflated the bill. Need injection blocking, DRT help, and cost protection. Stay on API Gateway.

A — wrong Shield Advanced only — it parses SQL in query strings.
B — wrong Move to NLB, attach WAF to the NLB, open a ticket for Shield Standard.
C — correct WAF on API Gateway (managed SQLi + rate rules) and Shield Advanced for DRT/cost protection. Standard is already on.
D — wrong IP denylist in Parameter Store checked inside every Lambda.

Case study 3 — rotate Aurora passwords

Stem

Aurora MySQL password sits in Elastic Beanstalk environment properties. Auditors want automatic 30-day rotation, no password in Beanstalk, secret encrypted at rest. Cost-sensitive but rotation is mandatory.

A — wrong Parameter Store SecureString plus a homemade cron that runs ALTER USER.
B — correct Secrets Manager with managed Aurora rotation; app retrieves the secret at runtime.
C — wrong Enable GuardDuty — it rotates credentials when it detects compromise.
D — wrong Switch only to IAM DB auth and skip a secrets product; the stem asked for password rotation.

Tricky points (still explained simply)

KMS Encrypt is not for big files. Use envelope encryption or SSE-KMS.

Key policy is mandatory for KMS. IAM alone often fails.

WAF ≠ Shield. HTTP rules vs network/volumetric DDoS.

CloudFront ACM certs live in us-east-1. ALB certs live with the ALB Region.

Detective services have different jobs. GuardDuty = threats; Inspector = CVEs; Macie = PII in S3; Hub = aggregate.
