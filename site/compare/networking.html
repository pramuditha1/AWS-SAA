Networking picker — stay private, then stay cheap, then go global

High-score pageDomains 1.2, 2.1, 3.2 · VPC, hybrid, edge

Networking stems are constraint puzzles. Security forbids the internet. Finance forbids NAT. The app needs HTTP path routing — or a static IP and TCP. Two VPCs need to talk — or forty VPCs plus a datacenter. AWS has a named tool for each sentence. Refuse the tool that works but breaks cost, privacy, or the layer the stem implied.

Start here — the W questions

Why

Apps must reach S3 without the public internet, talk across VPCs, reach the office, and serve users worldwide. Each need has a different AWS primitive. Using NAT “because it works” when a free gateway endpoint exists is a classic cost miss.

What

This picker chooses among gateway vs interface VPC endpoints, PrivateLink, peering vs Transit Gateway, Site-to-Site VPN vs Direct Connect, ALB / NLB / GWLB, CloudFront, and Global Accelerator — plus security groups vs NACLs.

Where

A VPC is Regional. Subnets sit in one AZ. Gateways and endpoints attach to the VPC. CloudFront and Global Accelerator sit at the edge (global). Hybrid links (VPN / Direct Connect) join your datacenter to AWS.

Which pieces matter

Gateway endpoint vs NAT · interface / PrivateLink · peering non-transitive vs TGW hub · VPN this week vs DX dedicated · ALB vs NLB · CloudFront vs Global Accelerator · SG stateful vs NACL stateless. Those ideas cover almost every networking stem.

Core knowledge — how to walk a stem

Private first, then cost, then layer

Private subnet + S3 or DynamoDB + no internet + lowest cost → gateway VPC endpoint (prefix-list routes, no hourly charge, same Region). The trap is a NAT Gateway — it works and bills you. An interface endpoint for S3 also works (private IP, costs more) and is right when on-premises clients need a private IP over VPN/DX.

Many networks. Two VPCs, simple, no overlapping CIDRs, no transitivity needed → VPC peering. Peering is not transitive: A–B and B–C does not give A–C. Three+ VPCs, messy mesh, or VPCs plus on-premises → Transit Gateway (hub that is transitive).

Hybrid timing. Encrypted hybrid needed this week → Site-to-Site VPN. Consistent private bandwidth with lead time OK → Direct Connect. DX is a private circuit, not IPsec by default — if the stem says “must be encrypted,” add a VPN overlay (or MACsec where offered). VPN now, DX later, both into TGW, is a standard design.

Load balancer layer. Layer 7 HTTP, host/path rules, WAF → ALB (often CloudFront in front for public HTTP). Static IP, TCP/UDP, TLS passthrough, huge connection counts → NLB. Inspect all VPC traffic with third-party firewalls → Gateway Load Balancer.

Security groups vs NACLs. Security groups are stateful, on ENIs, allow-only. NACLs are stateless, on subnets, need both directions, can explicit deny, numbered rules. Ephemeral return ports bite people on NACLs. Deny a bad IP across a subnet quickly → NACL. “This fleet may talk to this RDS on 3306” → security group referencing another security group.

Case study 1 — S3 from private subnets without burning money

Stem

Private EC2 instances must GetObject and PutObject against a bucket in the same Region. The VPC has no internet gateway. Security forbids the public internet. Cost should be as low as possible.

A — correct Gateway VPC endpoint for S3. Route-table prefix list, traffic stays on the AWS network, no hourly charge.
B — wrong NAT Gateway plus IGW. Violates “no public internet,” and you pay hourly and per-GB. Also there is no IGW today.
C — wrong Interface endpoint for S3. Works and gives a private IP, but costs more. Correct for on-premises over DX/VPN, not for in-VPC EC2 with a cost constraint.
D — wrong Public IPv4 on each instance. Violates “no internet.”

Gateway endpoints are for same-Region S3/DynamoDB from VPC route tables. Cross-Region needs another pattern. The exam usually stays in-Region for this item.

Case study 2 — forty VPCs and a datacenter

Stem

A company has 40 application VPCs in one Region and an on-premises datacenter. Every VPC must talk to every other VPC and to on-premises. Overlapping CIDRs are not an issue. Peering mesh is unmanageable. Encrypted connectivity to on-premises is required this month; dedicated bandwidth can come later.

A — wrong Full peering mesh. Not transitive; 40×39/2 links. This is the problem Transit Gateway solves.
B — correct Transit Gateway attaching every VPC, plus a Site-to-Site VPN attachment for on-premises now. Add Direct Connect to the same TGW later.
C — wrong One shared VPC and RAM only. Shared VPC helps with subnets; it is not the routing fabric for 40 isolated app VPCs plus a DC.
D — wrong Direct Connect this week with no VPN. DX is not instant; the stem said this month and encrypted.

VPN now, DX later, both into Transit Gateway. VPN overlay on DX adds IPsec if the stem demands encryption on the dedicated path.

Case study 3 — HTTP at the edge vs TCP anycast

Stem

A global user base opens a mobile API over HTTPS. They need caching of GET responses, AWS WAF, and a private S3 origin for static assets. A second workload is a real-time game protocol over TCP that needs static anycast IPs and regional failover — not HTTP caching.

A — wrong Global Accelerator for both. GA does not cache HTTP and does not replace WAF + OAC for S3.
B — correct CloudFront + WAF + Origin Access Control for the API/ALB and S3; Global Accelerator in front of regional NLBs for the game protocol.
C — wrong Route 53 latency routing alone for the HTTP API. Finds a close Region; does not cache or attach WAF at hundreds of edge locations the way CloudFront does.
D — wrong API Gateway plus CloudFront for the game TCP protocol. API Gateway is HTTP/WebSocket, not arbitrary TCP.

CloudFront = HTTP(S) CDN, WAF, OAC. Global Accelerator = static anycast IPs, TCP/UDP, health-check failover. Route 53 is DNS in the path of both — not the CDN and not the anycast fabric.

Tricky points

NAT vs gateway endpoint. NAT = general internet (patch repos, third-party APIs). Gateway endpoint = S3/DynamoDB. Using NAT for S3 is the cost trap.

IPv4 vs IPv6 egress. NAT Gateway is IPv4. IPv6 uses an egress-only internet gateway.

Public vs private subnet. A subnet is public when its route table points 0.0.0.0/0 at an IGW. NAT Gateways live in a public subnet.

Security groups are stateful. You do not open ephemeral return ports on the SG. You do on a NACL.

Direct Connect is not IPsec by default. Private circuit ≠ encrypted. Add VPN overlay or MACsec when the stem demands encryption.

Gateway Load Balancer is bump-in-the-wire for firewall/IPS appliances — not a substitute for ALB.
